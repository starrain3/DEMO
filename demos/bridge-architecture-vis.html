Architecture Review

VS Code Antigravity Bridge 核心架構與 Workflow 全景評審

CDP Port: 9222
雙向通訊橋接引擎 • 本地專屬工具

系統拓撲與端到端通訊架構

本工具解決使用者「離開電腦時仍需監控與操作 VS Code 內 Antigravity AI」的痛點。藉由 Telegraf 建立 Telegram 機器人服務，透過 Chrome DevTools Protocol (CDP) 穿透並操縱 VS Code 的 Webview DOM，實現指令雙向投遞、實時打字心跳、自動狀態收斂與安全回傳。

Client Layer

Telegram App

使用者隨身端。發送對話、控制指令（/stop, /new, /status）並接收分段回覆與進度心跳。

Allowed User ID 白名單防護
Bridge Engine

Telegraf Node.js 服務

非同步派發機制（消滅 90s 超時）、定時打字心跳發送器、3500 字長訊息智慧分段器。

bridge.js + .env (本地封閉)
Protocol Layer

CDP 連線管道

Puppeteer 透過 `http://127.0.0.1:9222` 連線 VS Code，建立目標 Target 獨立 CDPSession。

Runtime.evaluate + DOM Events
Target Layer

Antigravity Webview

雙保險文字注入、按鈕狀態嗅探（Cancel/Stop 與 Send）、多層 Markdown 清理萃取。

VS Code Extension Webview

Workflow 1：開機探針與 Webview 輸入框鎖定流程

VS Code 內部可能同時存在數十個 Webview Target（如延伸模組面板、設定檔、終端機等）。Bridge 不採用易失效的靜態 URL，而是實作「**DOM 語義特徵探針**」，主動探索每個候選 Target 是否存在 [aria-label="Message input"]。

輪詢重試防護

開機時自動進行 20 次探測（每次間隔 1.5s），即使使用者在開機時側邊欄尚未展開，只要使用者隨後點開側邊欄即可自動連線並發送就緒通知。

資源安全釋放

探測無效 Target 時強制在 finally 區塊執行 client.detach()，絕不殘留無用 CDP 連線，防止 VS Code 記憶體洩漏。

專案綁定確認

開機推播明確告知當前綁定的專案名稱（例如 TARGET_PROJECT_NAME=ku_tools），確保使用者在 Telegram 上操作不會誤指派至其他視窗。

Workflow 2：雙向指令注入、動態心跳與收斂萃取流程

這是 Bridge 最複雜的核心流程，涵蓋「雙重輸入保險注入」、「心跳防 Telegram 逾時」、「三連續確認結束防抖」以及「乾淨 Markdown 內容提取」。

雙重輸入保險機制 (Dual Injection Insurance)

VS Code Webview 採用 Draft/Lexical 類型之富文本輸入框。第一道使用 execCommand('selectAll') + execCommand('insertText')，若偵測到文字為空，立即無縫啟動第二道 ClipboardEvent('paste')，並派發 input 與 change 事件，確保 100% 成功填入。

動態耗時心跳 (Anti-Timeout Heartbeat)

Telegram 輪詢若未在 90 秒內回應用戶將發生連線超時中斷。Bridge 採用非同步事件隔離，主線程每 4 秒向 Telegram 伺服器發送 typing 動作，每 12 秒動態更新訊息上的已執行秒數，讓使用者在手機端清楚知曉 AI 仍在即時思考。

結束判定三重防抖 (Debounced Completion)

Agent 呼叫工具或思考切換時，Cancel 按鈕可能產生微秒級閃爍。Bridge 規定：只有在「Cancel 按鈕徹底消失」且「Send message 按鈕回歸」且「最新輪次 Markdown 渲染穩定」連續 3 次檢查都通過（約 3.6 秒防抖），才判定為正式完成。

純淨回覆萃取與安全切片 (Clean Parser & Chunking)

回覆萃取時會自動複製節點並刪除包含 worked-for、thought、讚/倒讚與工具按鈕的 DOM 節點，精準提取純內文。發送時若超過 3500 字則自動分片傳送，且若 Markdown 解析出錯時自動降級為純文字，絕不噴錯中斷。

Workflow 3：遠端控制指令系統 (/stop, /new, /status)

除了傳送常規對話提示外，Bridge 亦支援直接透過 Telegram 遙控本機 Antigravity 的控制台按鈕。
指令別名 (Aliases) 底層 DOM / CDP 觸發行為 防呆與反饋設計 適用情境
/stop
/cancel, 暫停, 停止		 搜尋 button[aria-label*="Cancel"], button[title*="Stop"] 並執行 click() 若目前無任務執行中，自動提示「💤 閒置待命中無須暫停」 AI 陷入不符合預期的迴圈或耗時過長時緊急終止。
/new
/reset, 新對話, 開新對話		 優先點擊 [data-testid*="new-conversation"]，次要搜尋專案內 New Conversation 按鈕 自動回報成功點擊或提示未找到按鈕（如側邊欄收合時） 舊對話 Token 累積過長，需要開啟乾淨 Session 時。
/status
status, /狀態		 探測連線與是否存在 Cancel/Stop 按鈕 即時回報：🟢 本機連線正常！📌 狀態：⚡ 正在執行任務中 / 💤 閒置待命中 確認連線健康度或目前是否有背景任務正在跑。
/help
/start, help		 Telegraf 內建指令字典回傳 回傳完整 Markdown 格式之操作指南與支援語法 初次使用或查詢指令語法。

架構評審綜合結論 (Review Summary)
1. 高韌性與防抖設計

雙保險輸入注入與連續三次狀態防抖確認，徹底克服富文本輸入框易卡死、以及 AI 工具呼叫瞬間按鈕閃爍導致的誤判提早結尾問題。

2. 零逾時的使用者體驗

透過 Telegram 原生 typing 動作與定時秒數編輯心跳，既避免觸發 Telegram 90 秒輪詢超時，又讓手機端即時感知電腦端工作狀態。

3. 嚴謹的本地安全邊界

嚴格鎖定白名單 User ID，且專案規範嚴禁 Push 至 GitHub，敏感 Token 永不洩漏，保障本機環境極高資安防護水準。
