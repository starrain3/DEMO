# 沖繩旅遊行程手冊編輯與維護工作流程 (Okinawa Travel Editor Workflow)

本技能指導 AI 與開發者如何正確、安全且符合 DEMO 規範地維護沖繩自駕 4 天 3 夜遊記手冊及行前檢核表。

---

## 🎯 核心原則與嚴格禁忌

1. **嚴禁直接編輯產出目錄**：
   - ❌ 嚴禁編輯 `DEMO/dist/demos/okinawa-*.html`
   - ❌ 嚴禁編輯 `DEMO/demos/okinawa-*.html`
   - ✅ **所有改動必須在 `DEMO/src_demos/` 原始碼目錄下進行**。
2. **加密建置發布規範**：
   - 任何原始碼改動完成後，必須更新 `package.json` 版號，並執行 `npm run build` 進行 AES-256 加密編譯發布至 `dist/`。

## 🚀 標準編輯與發布 SOP

當使用者提出修改或擴充沖繩行程需求時，請依循以下步驟執行：

### 步驟 1：確認修改需求並定位區塊
釐清使用者欲修改的景點、天數、餐廳、備案或視覺元件，於 `DEMO/src_demos/okinawa-travel-journal.html`（或檢核表）精準定位相應 HTML 結構。

### 步驟 2：執行程式碼編輯
- **樣式規範**：維持 Tailwind CSS 類別、Lucide Icons 圖標與深色 Ocean 琉球海洋主題風格。
- **資訊完整度**：新增或替換景點時，務必補齊：
  1. 景點卡片標題、建議停留時間與簡介
  2. Google Maps 導航地標超連結
  3. 電話號碼複製按鈕（方便輸入車載 GPS）
  4. 🤖 AI 額外延伸私房攻略（包含停車位、省錢秘訣或老饕點單）
  5. 戶外景點需附帶「雨天備案（Rain Backup）」切換盒

### 步驟 3：同步清單索引（若適用）
若改動涉及頁面標題、核心簡介或標籤，同步更新 `DEMO/src_data/demos.json` 中的 `okinawa-travel-checklist` 或 `okinawa-travel-journal` 項目。

### 步驟 4：遞增 package.json 版號
依修改幅度遞增 `DEMO/package.json` 中的 `"version"`：
- 修正文字、補充備案、微調樣式 ➔ 升級修訂號 (PATCH，例如 `1.4.1` ➔ `1.4.2`)。
- 新增功能模組、重大行程改動 ➔ 升級次版號 (MINOR，例如 `1.4.1` ➔ `1.5.0`)。

### 步驟 5：執行加密建置與驗證
在 PowerShell 終端機執行：
```powershell
Set-Location -Path "d:\ku_tools\DEMO" ; npm run build ; npm run verify
```
確保終端輸出顯示「打包成功」且「所有驗證測試通過」。

### 步驟 6：收尾與交付
完成後總結變更成果，並依據工作區後置規則向使用者進行延伸優化建議與詢問 GitHub 推送。
